# Сайт-портфолио Даниила: дизайн

Дата: 2026-09-04. Статус: согласован в обсуждении, ждёт реализации.

## 1. Зачем

Даниил сам находит клиентов и приходит к ним с предложением. Ему нужен один адрес,
который можно вставить в письмо или сообщение, и один PDF, который можно приложить.
Адрес должен продавать заказчику, PDF — работодателю. Обе аудитории обслуживаются
одним сайтом, но с разными входами.

**Аудитории по приоритету:**

1. Малый бизнес в РФ без своих разработчиков (салон, школа, клиника, магазин, турфирма).
   Покупает результат и спокойствие, стек не различает.
2. Небольшие продуктовые компании и стартапы с техническим основателем. Стек и качество
   кода им важны.
3. Работодатели (найм широко: практически любые предложения по бэкенду/фуллстеку).

**Что продаём.** Продукт — сайт, сервис, Telegram-бот, Mini App — сделанный под ключ и
сразу «под продвижение»: заголовки, разметка, семантика, скорость. Сопровождение и
реклама (Яндекс, VK) — не отдельная услуга-довесок, а честное предупреждение: продукт
без ведения (контент, статьи, кампании, обновления) через полгода перестаёт приносить.
Подача эксперта, который предупреждает, а не продавца. Кто именно ведёт кампании — на
витрине не упоминается.

**Цены на сайте не называются.** Стоимость сильно плавает от клиента к клиенту и
обсуждается в переписке. Вместо цены якорем доверия работают кейсы и чёткое «что входит».

## 2. Решения, принятые в обсуждении

| Вопрос | Решение |
|---|---|
| Главный вход | Для заказчиков; найм — второй вход, ссылка только в подвале |
| Форма предложения | Направления без цен («стоимость зависит от задачи — напишите, посчитаю за день») |
| Язык | Только русский |
| Контакт | Три кнопки: Telegram, MAX, почта. Форм и чат-виджетов нет |
| Найм | Страница `/cv` + `/resume.pdf` из одного источника данных |
| Хостинг | GitHub Pages, публичный репозиторий |
| Домен | Свой `.ru` поверх Pages; до покупки — `<логин>.github.io` |
| MainExperts | Показывается **анонимно**, только скриншоты с замазанным брендом, без названия и ссылки. Согласие владельца — за Даниилом |
| Скалистый Берег | В резерве (`draft: true`), в сетку не выводится |

## 3. Главная страница `/` (для заказчиков)

Малый бизнес читает заголовки, не абзацы: каждый блок обязан работать, даже если
прочитан только заголовок. Порядок сверху вниз:

1. **Оффер.** Заголовок про результат: «Сайты, сервисы и Telegram-боты, которые приносят
   клиентов». Подзаголовок: «Даниил, разработчик. Делаю под ключ: от дизайна до запуска и
   сопровождения. Один исполнитель на весь проект — без агентских наценок и “это не ко
   мне”». Три кнопки контакта здесь же.
2. **Направления** — четыре карточки, в каждой 3–4 строки «что входит» и подпись про
   стоимость:
   - *Сайт для бизнеса* — лендинг, корпоративный, каталог; с заявками, аналитикой,
     готовый к рекламе и поиску.
   - *Telegram-бот и Mini App* — запись, заказы, уведомления, каталог внутри мессенджера;
     MAX и VK тоже. Внутри карточки — компактный блок «Ещё боты»: одна строка на бота
     (что делает, для кого) для мелких ботов, которым не нужна отдельная страница.
   - *Сервис / личный кабинет / админка* — CRM, учёт, платежи, интеграции.
   - *Сопровождение и развитие* — обновления, контент, статьи, рекламные кампании.
3. **Кейсы** — сетка карточек, см. §4.
4. **Как работаем** — четыре шага: разговор и ТЗ → прототип и дизайн → разработка с
   промежуточными показами → запуск, обучение, гарантия. Честно про сроки: лендинг —
   1–2 недели, сервис — от месяца.
5. **Почему продукт без ведения не работает** — короткий блок голосом Даниила, как
   предупреждение, не как продажа. Одна фраза: «могу вести сам или подключаться по
   необходимости».
6. **Для технических заказчиков** — маленький блок: стек (Rust, React, TypeScript,
   PostgreSQL/MySQL, Telegram Bot API), «код остаётся у вас», ссылка на GitHub.
7. **Контакты** — три кнопки повторно, город и часовой пояс.

Подвал: ссылка «Резюме» на `/cv`, ссылка на GitHub.

**Чего нет:** отзывов (пока их нет — выдуманные видно), счётчиков «150 проектов»,
всплывающих окон, чат-виджетов, тёмной темы «под разработчика».

## 4. Кейсы

**Карточка в сетке:** обложка-скриншот, ниша одной строкой, результат одной строкой,
метка роли: *фронт* / *фронт + бэк* / *под ключ*.

**Страница `/cases/<slug>`**, единый шаблон:

1. Шапка: название, ниша, год, ссылка на живой сайт или «закрытая система, под NDA».
2. Задача — 2–3 предложения на языке клиента.
3. Что сделал — список глаголами («спроектировал», «собрал», «подключил»). Стек не
   упоминается, кроме случаев, где он и есть результат (illoca: WebGL-сцены, анимации).
4. Результат — что получил клиент; цифры, если есть; иначе качественно, без придуманного.
5. Галерея — 3–6 скриншотов, десктоп + телефон, WebP. Для NDA и MainExperts — только
   скриншоты с замазанными названиями.
6. Призыв: «Похожая задача? Напишите» + три кнопки.

**Порядок в сетке:**

| # | Кейс | Роль | URL / статус |
|---|---|---|---|
| 1 | illoca | фронт | https://illoca.unseen.co/ — Nuxt 3, three.js + шейдеры, GSAP, Lenis; стек здесь уместен |
| 2 | Оштен-Тур | фронт + бэк | https://oshten-tur.ru/ |
| 3 | Платформа онлайн-образования и профориентации (MainExperts) | под ключ | анонимно, скриншоты; кабинеты, оплаты, PDF-отчёты, бот, Mini App, админка |
| 4 | ARB365 | под ключ + бот | https://arb365.net/en — бот, платежи CryptoCloud, соцлогин, дашборд |
| 5 | Аналитическая платформа по футболу и киберспорту | под ключ | NDA, только скриншоты и обобщённое описание |
| 6 | ЭкономЭнерго | фронт + бэк | https://economenergo.com/ — много разделов, формы, капча, обратный звонок, подписка |
| 7+ | Telegram-боты | под ключ | один-два самых интересных (транскрибация аудио в текст, парсер-боты) — полные страницы; остальные — строкой в «Ещё боты» |
| — | Скалистый Берег | фронт | https://skbereg.ru — `draft: true`, в резерве |

Четыре из публичных сайтов сделаны на October CMS — в текстах кейсов это не
упоминается, чтобы не спорить с позиционированием Rust + React; заказчик оценивает
результат.

**Условия перед публикацией:**

- skbereg.ru отдаёт в HTML незаинтерпретированный `<?php echo time();?>` (6 раз). Пока
  кейс в резерве, это не блокер; если включать — сначала починить в шаблоне
  (`{{ 'now'|date('U') }}`) или показывать без ссылки.
- Клиентам, чьи сайты показываются со ссылкой, стоит написать «покажу ваш сайт в
  портфолио, не против?». Решение Даниила, не блокер.

**Формат хранения:** `src/content/cases/<slug>.md` с полями `title`, `niche`, `role`,
`year`, `url` (опционально), `nda` (bool), `cover`, `result`, `order`, `draft`; тело —
разделы «Задача / Что сделал / Результат». Скриншоты — `public/cases/<slug>/`.
Добавить кейс = добавить файл и папку.

## 5. Страница `/cv` и PDF

**Один источник — `src/data/cv.yaml`:** имя, заголовок, контакты, о себе (3–4 строки),
стек по группам, опыт (период, роль, 3–5 пунктов результатов), образование, языки.

Правила текста CV:

- Всё в **прошедшем времени**, без «сейчас работаю над» — работодатель должен видеть,
  что фокус будет на нём.
- Заголовок при широком найме: «Fullstack-разработчик · Rust / React / Go / PHP».
  Первый абзац: «4+ года, делаю продукт целиком: фронт, бэк, боты, инфраструктура».
- Кейсы — те же, но одной строкой каждый и **со стеком** (работодателю он важен).

Из YAML собираются:

- **`/cv`** — HTML в стиле сайта, но строже: без анимаций, печатается в 1–2 страницы
  через `Ctrl+P`. Вверху кнопка «Скачать PDF» и три контакта.
- **`/resume.pdf`** — Typst-шаблон `cv/resume.typ` читает тот же YAML через `yaml()`,
  компилируется в GitHub Actions при каждом пуше. Один лист A4. Имя файла для
  скачивания — `Daniil_Eskov_CV.pdf`.

## 6. Технология и репозиторий

**Стек:** Astro 5 + React 19 (острова только там, где есть интерактив: галерея кейса)
+ Tailwind 4 + TypeScript. Typst для PDF. Никаких CMS, БД, серверов.

Почему не SPA на Vite + React: пустой HTML до загрузки JS и костыль с `404.html` под
роутинг противоречат тому, что сайт обещает клиентам (разметка, скорость). Почему не
чистый HTML: React в репозитории не показан, семь страниц кейсов дублируют шапки
руками.

**Репозиторий** — `<github-логин>/<github-логин>.github.io`, публичный: это витрина
кода для технического заказчика и работодателя. README на русском.

```
src/
  pages/            index.astro, cv.astro, cases/[slug].astro
  components/       Astro-компоненты (статика) + React (галерея)
  content/cases/    *.md — по одному на кейс
  data/cv.yaml      единый источник для /cv и PDF
  styles/
public/
  cases/<slug>/     скриншоты WebP
  CNAME             домен
cv/resume.typ       Typst-шаблон
.github/workflows/deploy.yml
```

**Деплой:** push в `main` → Action: `npm ci` → `astro build` →
`typst compile cv/resume.typ dist/resume.pdf` → публикация в Pages. Ручных шагов нет,
превью PR не делаем.

**SEO и качество — сайт как доказательство обещаний:** семантическая разметка,
`<title>`/`description` на каждой странице, Open Graph-картинки (карточка при отправке
ссылки в Telegram/MAX), `sitemap.xml`, `robots.txt`, JSON-LD `Person`. Цель — Lighthouse
100/100/100/100 на главной, проверяется перед первой публикацией. Яндекс.Метрика —
счётчик для отслеживания заходов по рассылкам.

**Визуал:** сдержанный «студийный» — светлая тема, одна акцентная краска, крупная
типографика, много воздуха, обложки кейсов как главный визуальный элемент. Не
«портфолио разработчика с тёмной темой и терминалом»: читатель — владелец салона.
Конкретный макет (цвет, шрифт) — на этапе реализации.

**Домен:** `.ru` у любого регистратора; DNS — четыре `A`-записи GitHub Pages и `CNAME`
для `www`; HTTPS выпускает GitHub. Почта `hello@<домен>` — Яндекс 360 для бизнеса,
бесплатный тариф. Пока домена нет, сайт живёт на `github.io`.

## 7. Что нужно от Даниила на этапе наполнения

- GitHub-логин, ник в MAX, адрес почты, имя домена.
- Скриншоты NDA-платформы и MainExperts (или доступ, чтобы снять).
- Список Telegram-ботов: что делает, для кого; какие один-два заслуживают страницы.
- По каждому кейсу — ответы на 3–4 вопроса: что было до, что просил клиент, что
  оказалось сложным, что получилось.
- Для CV — места работы/проекты с периодами и ролями, образование.

## 8. Вне объёма

Английская версия, отзывы, формы заявок, блог, тёмная тема, превью PR, платные
сервисы. Всё это добавляется отдельными задачами, если понадобится.
